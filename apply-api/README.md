# Admission enquiry API

The `/apply` enquiry form submits JSON to `/apply-api/apply-submit.php`.
On cPanel, upload this folder to `public_html/apply-api/`. The handler
uses the configured database connection and inserts into the `application` table.

The SQL insert uses only these standard columns: `name`, `mobile`, `email`,
`location`, `course`, `message`, `other`, `previous_qualification`,
`course_level`, and `academic_qualification_marks`. It does not run migrations,
create columns, or alter the database. The `id` column is generated by
the existing auto-increment primary key.

The form level (`UG`, `PG`, or `Ph.D`) is stored in `course`. The selected level
and preferred department are both preserved together in `course_level` because
the table has no separate department column. Location values are joined into
the existing 50-character `location` field. `other` records the source as
`Website`. The academic qualification / marks answer is stored in
`academic_qualification_marks`.

For local development, `local-server.mjs` intercepts the same endpoint and
saves submissions to the local SQLite database.
That SQLite database mirrors the schema; it does not affect cPanel.

## Local testing

Start the site from the repository root:

```bash
node local-server.mjs
```

Open `http://127.0.0.1:4173/apply` and submit the form. The local server
validates and saves the enquiry locally.
